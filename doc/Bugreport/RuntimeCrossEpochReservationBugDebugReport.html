Runtime 跨调度轮次预约提前释放 Bug Debug 报告

范围：InProcessRuntime 提前删除虚拟未来仍然有效的预约，导致跨调度轮次并发检查缺少旧任务。

平台修改文件：mars/runtime/inprocess.py

新增回归测试：tests/test_runtime_cross_epoch_reservations.py

一句话结论：Runtime可以立即计算任务未来的完成时间，但不能立即删除该任务在未来时间段内的资源预约；修复后，预约保留到虚拟结束时间，跨轮次任务也会参与CPU、GPU、内存和并发校验。

1. Bug成因

1.1 两套预约表发生分裂

Coordinator通过完成事件堆和active_resource_reservations保留未完成任务；Runtime通过内部_ResourceReservation检查真实派发是否符合资源和并发上限。

原版receive_completion()不等待虚拟结束时间，立即调用agent.release()。而release()直接执行：

reservation = self._reservations.pop(reservation_id, None)

因此，Coordinator仍认为任务尚未到完成时间，Runtime却已经忘记了它。

1.2 为什么同批次检查有效、跨批次失效

同一批任务会连续完成dispatch()，之后事件循环才运行receive_completion()。所以同一批后派发任务仍能看到先派发任务。事件循环让出控制权后，本批预约被提前删除，下一批任务便看不到上一批仍在虚拟执行的任务。

2. 固定复现场景

三个早期轮次的数据压缩任务在Runtime中被提前删除；第二批定位任务因此忽略这三个占用。Noise使两个定位任务短暂重叠，Coordinator最终看到3 + 2 = 5，超过并发上限4。

修复前测试结果：PlanValidationError: node edge-1 exceeds max_concurrency at 576.6980429224418

3. 最小Diff

3.1 修改前

def release(self, reservation_id, finished_time_ms, *, ok):
    reservation = self._reservations.pop(reservation_id, None)
    ...

async def receive_completion(self, dispatch_id):
    ...
    agent.release(
        reservation.reservation_id,
        completion.finished_time_ms,
        ok=completion.ok,
    )

3.2 修改后

def release(
    self,
    reservation_id,
    finished_time_ms,
    *,
    ok,
    retain_until_finish=False,
):
    reservation = self._reservations.get(reservation_id)
    if not retain_until_finish:
        self._reservations.pop(reservation_id, None)
    ...

async def receive_completion(self, dispatch_id):
    ...
    agent.release(
        reservation.reservation_id,
        completion.finished_time_ms,
        ok=completion.ok,
        retain_until_finish=True,
    )

正常虚拟完成只记录结果，保留预约时间段；取消、派发失败和异常完成仍立即删除预约。

3.3 过期记录清理

def _discard_expired_reservations(self, now_ms):
    删除 scheduled_finish_ms <= now_ms 的预约

新一轮inventory(now_ms)及最终报告时清理过期记录。即使尚未物理删除，时间已经超过finish_ms的记录也不会被资源检查算作占用。

6. 最终结论

Bug2已用最小范围修复：平台只修改InProcessRuntime内部预约生命周期，没有修改Coordinator、Scheduler、Engine、Optimizer或数学目标函数；跨轮次任务现在共享同一份有效的Runtime时间表。
